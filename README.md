# soma3d · 从 2D 木偶到 3D 步态

C++ 物理内核 + WebSocket + three.js 实时渲染。2D 版（`/sdcard/dsh/soma-v2/`）保留为参考实现，
3D 版是它的一次「换轴」重写：矢状面之外多了冠状面的动力学。

## 跑起来

容器内（可执行的副本在 `/root/work/soma-v3/`，`/sdcard` 是 noexec，只放源码）：

```bash
cd /root/work/soma-v3
node server.js          # 起在 8123
# 浏览器打开 http://127.0.0.1:8123
```

独立自检（不开浏览器也能验）：

```bash
cd /root/work/soma-v3/cpp && g++ -O2 -std=c++17 -o soma3d main.cpp
./soma3d --selftest     # 12 组断言
./soma3d --bench        # 物理耗时
./sweep                 # 0.4~1.9 m/s 速度扫描
```

## 结构

```
cpp/vec.h       最小 V3 数学
cpp/walker.h    物理内核：LIPM 水平动力学 + 2-link 解析 IK + 18 节点/17 骨骨架
cpp/ragdoll.h   体模型：18 个质量球 + 距离/弯折/自碰撞/地面约束（PBD），摔倒后接管
cpp/main.cpp    --selftest / --bench / --serve（stdin 指令、stdout 60Hz JSON 帧）
server.js       静态文件 + WebSocket 桥，把 C++ 的帧转给浏览器
web/app.js      three.js 场景：关节球 + 骨骼圆柱 + 脚掌 + CoM/CaP/ZMP 三个地面标记
```

## 协议

浏览器 → 内核（一行一条，纯文本）：
```
walk | run | stop
push <fx> <fy> <fz>     速度脉冲（m/s）
fall                    强制侧向推倒（3 m/s），看体模型接管
vdes <v>                目标速度 0~2.0
reset <mode>
```

内核 → 浏览器（每 1/60 s 一行 JSON）：
```json
{"t":12.3,"mode":1,"falls":0,"speed":0.85,
 "com":[8.17,0.02],"cap":[8.42,0.04],"zmp":[8.13,-0.01],"lean":[0.01,0.02],
 "duty":1.0,"err":0.0,
 "nodes":[[x,y,z,r,contact] × 18],
 "bones":[[a,b] × 17]}
```
节点顺序：0 骨盆 · 1 胸 · 2 颈 · 3 头 · 4-6 左肩/肘/手 · 7-9 右肩/肘/手 ·
10-13 左髋/膝/踝/脚 · 14-17 右髋/膝/踝/脚。

## 和 2D 的差别

| | 2D（soma.js） | 3D（soma3d） |
|---|---|---|
| 状态 | 每节点 x/y/vx/vy | 骨盆 x/z/vx/vz + 2 只脚的摆动状态 |
| 前后 | mocap 表 + cmdRate 前馈 | 速度伺服（和 2D 同款，速度精确） |
| 侧向 | 无（冠状面不存在） | **真 LIPM**：ẍ=ω²(x−zmp)，CoP 限制在支撑多边形内 + 捕获点落脚 |
| 骨架 | 18 节点 17 骨，2D IK | 同上 3D，2-link 解析 IK，膝朝向 +x |
| 摔倒 | 没有这个状态 | 捕获点（相对支撑中心）越界 0.15 s → 体模型接管，真的倒下去躺平 |
| 速度 | ~219 px/s | 0.4~1.9 m/s（扫描全绿） |

**这一版最值得看的**：走路时侧向推 0.9 m/s，重心横移 0.14~0.24 m 就靠下一步接住了，
不是被外力硬拽回来的 —— CoP 只能待在脚掌里，接不住就是真摔。

## 场景与指令

默认场景带一段 0.12 m 的台子（`x0=2.5, x1=6.5`）。进程启动时会先打一行
`{"world":[{...}]}`，`server.js` 存下来补发给每个新连接，网页据此画方块。

| 指令 | 作用 |
|---|---|
| `walk` / `run` / `stop` | 换步态 |
| `vdes 1.2` | 直接给目标速度（0~2.0 m/s） |
| `push fx fy fz` | 推一下（N·s/kg → 速度脉冲） |
| `ff 秒数` | 物理快进，最多 3600 s（看疲劳/体温用） |
| `mu 系数` | 地面摩擦（0~1.5，冰面 0.05 / 水泥 0.9） |
| `mu 系数` | 地面摩擦（冰面 0.05、水泥 0.9），摔倒后滑多远看它 |
| `fall` | 强制侧向推倒（3 m/s） |
| `getup` | 起身（体模型靠"肌肉"自己站回来） |
| `reset m` | 复位 |

HUD 右上角：`拖动 = 转视角`、`滚轮 = 远近`、`F = 推倒`、`G = 起身`。

## 地面反作用力

每帧输出 `grfL/grfR`（N，世界系）、`cop`、`mu`。网页上从两只脚踝各画一支箭头，
长度 ∝ 合力（700 N ≈ 0.5 m）。站着时两脚合计正好等于体重；跑步的腾空相里箭头会消失。

## 生物层（`cpp/bio.h`）

不驱动关节，是"事后解释"：姿态 + 地面反作用力 → 逆动力学 → 肌肉激活 → 耗能/疲劳/体温。
疲劳和体温会反过来压速度（累到 0.7 只剩 65%，体温 >39.5 °C 再砍一半）。

HUD 上多了三行：**代谢**（W）、**疲劳**（0~1，>0.3 变黄、>0.5 变红）、**体温**（°C）。
想快速看到它：跑起来以后发 `ff 600` 快进 10 分钟，再 `stop`。

## 脊髓层（CPG）

节律不是外部时钟：两条腿各一个振荡器（`cpp/cpg.h`），耦合维持反相，
触地时把该腿的相位拉回支撑相起点。上层只能改**频率/幅度/开关**，碰不到关节角。
`Walker::spinal = false` 可切回旧的相位计数器（对照用）。

## 意图（没有模式按钮）

界面只有一个滑块「想走多快」。站着 / 走 / 跑由 `Walker::intentMode` 自己切
（超过 1.15 m/s 切跑）；停下要等重心落回支撑范围才算站定。
指令：`intent <v>`（0~2 m/s）。

## 生物层压脊髓（不是压速度）

疲劳不只会让人走得慢，还让人**迈得慢、抬不起脚**：
`fatGain = 1 - 0.45·fat`，直接乘在步态周期和抬脚高度上。
意图 0.8 m/s、疲劳 0.6 时：步态周期 1.008 → 1.476 s、抬脚 0.070 → 0.053 m、实际速度 0.65。

演示指令：`fat 0.65`（直接设疲劳）+ `intent 0.9`。

## 大脑通道（异步）

脊髓不调 LLM。心里没数时写 `brain.pending + tag`，然后照常跑；
大脑回来带同一个 tag，迟到的丢弃；0.6 s 没回就自己决定。
指令：`brain`（假装挂起）、`answer <tag> [vDes]`。HUD 有一行「大脑」。

## 借步恢复

站着被推歪（`|p.z−cen.z|>0.13` 或 `|v.z|>0.35`）会迈一步把重心接回来，不再硬撑。
侧推 1.4 m/s 能站住，2.2 m/s 以上该倒就倒。

## 已知边界

- 前后不是动力学：p.x 直接跟着 vRef 走（要真动力学得换求解器，那是 v4 的事）。
- 侧向的「髋策略」是一段饱和 PD（上限 3 m/s²），代表关节力矩上限，不是无限外力。
- 目标速度超过 2.0 m/s 会散架（周期自适应只在设计范围内有效），已在协议层钳住。
- 摔倒之后起身是瞬移（按 W/R 直接 reset），还没有起身动作。
- 体模型只在摔倒时接管，站立/行走时的碰撞体还没参与（下一块：障碍物、台阶、地面反作用力）。

## 体模型（`cpp/ragdoll.h`）

18 个有质量的球（总 70.0 kg，按 Dempster 段比例）+ 17 根距离约束 + 4 类补充约束：

| 约束 | 干什么 | 缺了会怎样 |
|---|---|---|
| 距离骨 | 骨长不变 | 腿会被拉长 |
| 弯折限位 | 隔节点最小距离（脊柱、颈、膝、肘） | 躯干像面条一样卷成一团 |
| 自碰撞 | 手 vs 胸腔、膝 vs 对侧髋 | 手臂插进胸腔 |
| 地面 | 球-平面，法向贴合 + 0.9 切向摩擦 | 沉进地板 / 一直滑 |

求解：Verlet 积分 + 位置投影（PBD），每帧 4 子步 × 8 迭代，质量加权。
实测：侧推 3 m/s → 倒下 → 质心 0.075 m 躺平 → 1 s 内静止，骨长残差 0.0000。
- 走路时脚掌朝向固定朝 +x，没有 yaw 转身。

## 模型调教（mocap → 她自己的身体 → 先验）

两条路都试过，记录在这里免得下次再走一遍。

**CMU mocap（124 段 / 29 受试者 / 165 MB / 92,597 帧，`mocap/`）**：
- 抓取走 `cdn.jsdelivr.net` + `api.github.com`（HF 不可达，jsDelivr 偶发 403 是限流）。
- `tools/mocap/bvh2seq.cpp` → 每段一个 32 列 CSV（`u0, ph, q[10], dq[10], q_next[10]`）+ `.pose`（体坐标手臂偏移）。
- **两个坑**：① CSV 里的 `dq` 就是训练目标（前向差分），拿它当特征会得到"0.04°"的假精度——运行时喂的是后向差分；
  ② CMU 的 OFFSET 单位 ≠ 通道单位，`bodyScale` 必须用髋→踝腿长归一，否则骨头缩到 1/15、速度小 8.8 倍。
- **结论**：mocap 的关节角**不能**当这 10 维角空间的先验（两边用同一个 `SpinalCore::measure()`，
  但 CMU 骨架拓扑不同，量出来的分布完全不同：运行时 q0≈28°，CMU 走路≈−0.6°）。
  拿它训线性模型，跨受试者留出单步中位 1.13°，还不如"不动"基线。

**姿态先验（手臂）这条路暂时走不通**：修好 bodyScale 后 `.pose` 里的手臂偏移是
肩→腕 0.28 m、肩→肘 0.45 m（CMU 前臂本来偏短），但按相位 φ 拟合的前后摆幅中位只有 **0.015 m**
（最好的 08_07 是 0.151/0.085——"exaggerated stride"那种夸张步才有真人量级）。
原因是这批片段大多很慢（速度中位 0.58 m/s）且人站着/摆姿势；`PosePrior` 现在用的是她自己探索出来的数据，
换成 mocap 反而会让手臂更僵。

**她自己的身体（`--seqdump`）**：
- `./soma3d --seqdump out.txt --episodes 900` → 874 段、336,874 帧（60 Hz，22 s 跑完），随机速度/模式/转向/抬手/前倾/摆手。
- `tools/self_train.py` + `tools/selffit.py`：与 `spinal.h::feats` 逐位一致的 58 维特征，ridge，按 episode 8:2 留出。
- 结果：单步 0.88°，6 步 3.39°，24 步 5.22°（基线"冻结"6 步 6.12°、24 步 9.02°）。
  扩到 78/98/120 维特征只让 6 步好 0.3°，24 步反而更差 → **不值得动 DX**（改维度要同步 `spinal.h` 的 feats 与 `spinal_core.h` 的 `"DX":58` 校验）。
- 落盘：`assets/spinal_learned.json`（A 是 **58×10** = DX 行 × D 列，`load()` 逐行解析；JSON 必须紧凑写，`"DX":58` 中间不能有空格，否则 `load()` 直接拒收）。
- 收益只在盲推上：24 步盲推 8.50° → 2.47°（单步误差两边都是 0.011 rad——在线 LMS 不到 1 s 就收敛，
  所以**别指望换先验改善单步精度**）。`--spinaleval` / `--selftest §15` 都能量到。

## 步态对齐真人（`--gaitdump`）

`mocap/gaitstats.txt` 里 34 段真人走路/跑步的周期、步幅、抬脚高度：

| 速度 | 周期 | 步幅 | 步频 |
|---|---|---|---|
| 0.5~0.8 | 1.25 s | 0.77 m | 96 步/分 |
| 0.8~1.1 | 1.10 s | 0.95 m | 110 步/分 |
| 1.1~1.4 | 1.04 s | 1.27 m | 115 步/分 |

旧公式 `min(2*Tstep, 0.80/v)` 在 0.71 m/s 以上才生效，慢走偏快（1.095 s vs 1.25 s）。现在：

```cpp
float T = std::min(1.30f - 0.20f * v, 0.80f / v);   // 低速段按真人表，高速段保持原样
```

高速那边为什么不能也按真人表拉长周期：她的腿 0.45+0.45、骨盆高 0.895，`footTarget()` 的
`reachX ≈ 0.29 m` 把落脚点钉死，步幅再往上（1.05 m 时 err 0.012，1.41 m 时 0.096）IK 只能压短骨长，
0.9 m/s 以上还会连带台阶测试和速度扫描一起挂。**要真人那样长的步子得先改腿长（v4）。**

## 快脑：三秒之内决定她干什么

脊髓挂牌子（`{"brain":{tag,why}}`）之后要有人回答"现在该干什么"。
以前这条路是**投一句话进我这条主会话**再等回复 —— 主会话上下文几万 token，
光装配系统提示就好几秒，实测最长挂过 **240 s**，身体早自己拿主意了，问题还留在我的对话里。

现在是**独立的快脑**，不在任何对话里：

- 入口：plugin-body 的 `POST /soma3d/mind`（逻辑名 `/soma3d/brain`，route.json 把两者对上，server.js 每次现读）。
- 实现：`ctx.llm.prepareCall({provider, model, maxTokens, temperature})` + `ctx.llm.stream()`，
  **一次调用**，系统提示只有十行（SOMA 的身体 + 只要 JSON + 五条守则），`maxTokens 220`。
- 预算：默认 **2400 ms**，`AbortController` 硬掐；掐了就返回 `ok:false` 让本地兜底，绝不拖物理。
- 实测（deepseek-flash）：**0.79 / 0.90 / 1.07 / 1.17 / 1.65 / 1.78 s**，全部成功。
- 记录：每问一条写 `brain/session.jsonl`（时间、why、tag、ms、raw、解析出的 intent）——
  它自己就是一份"单独会话"的流水，面板「脑」页能看最近 8 条。
- server.js 那头 `SOMA_DSH_BRAIN_MS` 默认从 15000 降到 **3000**，两路（快脑 / 8082 本地模型）谁先回用谁。
- **慢脑**（`mode: 'session'`）：走 `soma-brain` 那个独立会话，记得住事但慢，
  等待上限 20 s（原来是 240 s）。`create` 撞 `session "soma-brain" already exists` 时改 `agents.resume`。
- **绝不再退回主会话**：老代码在独立会话建不起来时 fallback 到 `agents.roots()[0]`，
  那就是我自己 —— 她的问题会被塞进我的对话（踩过）。现在建不起来就报错。
- soma-body 插件里那条 `routeBrainToModel`（WS 帧 → `soma_body` 工具 → 主会话）默认关掉，
  配置 `brainRelay: false`。

面板「脑」页：模式（快/慢）、预算 ms、maxTokens、模型、保存、试一句（当场量延迟）、
统计（问了几次 / 答上来 / 平均 / p90 / 超时）和最近八条。这几条走
`/soma3d/api/brainlog` `/soma3d/api/braincfg`（8125 上转一手到 3080，页面不用猜后缀）。

**路由必须挂在 `ctx.effect` 里**：`apply()` 直接 `return` 的清理函数不会跑，
`webServer.register` 的路由就一直留着 —— 连 enable 六次把 `/soma3d/brain` 一族占满
（`brain`..`brain-6`），新的反而挂不上，只能顺延成 `-7` 或者干脆 null。
现在挂载路径改名成 `/soma3d/mind` `/soma3d/voice` `/soma3d/mindlog` `/soma3d/mindcfg`，
逻辑名照旧（`route.json` 的键还是 `/soma3d/brain`、`/soma3d/talk`，`web/app.js` 不用改）。
卸的时候把 `route.json` 对应项写回 `null`，免得 server.js 照旧后缀去问一个已经死掉的实例
（报 `cannot get required service "agents" in inactive context`）。

**超时必须在循环里判**：`AbortController` 没能掐断底层请求（预算 2.4 s，实测仍跑满 15 s）。
`for await` 里加 `if (timedOut || Date.now() - t0 > budget) { timedOut = true; break }` ——
break 会调用流迭代器的 `return()`，这才真的收掉。

## 基础行为：她会过日子了（2026-11-14）

### 一、为什么以前"只会原地打转、四肢乱飞"
全是 bug，不是"没调教好"。四类：

1. **摆臂相位** `main.cpp` 原来写 `armPh = fmod(W.t / cycleT(), 1)`：`W.t` 已经几百秒，
   而 `cycleT()` 随速度连续变，T 抖一点相位就跳掉大半圈 → 手一帧瞬移 0.47 m（实测）。
   改成 CPG 积分相位 `W.phase`；`walker.h:825` 的自摆臂同病同改。
2. **手臂永远满伸**：向量被无条件归一化到 0.28 / 0.54，再乘 `GAIN = 2.2`（只乘 x），
   手最远能到离肩 1.19 m（臂长只有 0.54）。改成"只许收不许撑"：肘 ≤0.30、手 ≤0.52，
   只放大前后摆 ×1.25（真人走路 0.2~0.3 m）。
3. **躯干一步一跳**：倾角直接跟 ZMP，每换承重脚 ZMP 从后脚跳到前脚（前后差 0.35 m），
   胸/颈/双臂一步抖 ±0.12 m。加 0.25 s 一阶平滑（`Walker::leanSmX/leanSmZ`）。
4. **`goto` 从来没生效过**：`goto X Z` 只在 `route` 分支里认（`route goto X Z`），
   大脑和习惯层发的每一条 `goto` 都是**静默丢弃**。现在 `goto` 是一等指令。
   顺带：边界原来是半径 **1.30 m 的圆**，屋子是 8×6.5 m —— 她被关在正中间一个
   2.6 m 的小圈里；大脑目标点又被夹在半径 1.05 的圆里。都改成矩形（±3.40/±2.80、±3.2/±2.6）。
   贴墙、背对目标时一律"先站住转身再走"（0.45 m/s 配 1.7 rad/s 转弯半径只有 0.26 m，
   一边走一边拧就是原地画圈）。

### 二、习惯层（`brain/behavior.cjs`）
以前每一拍都问大模型"现在干什么"，模型只会回一个点 + 一个速度，于是行为永远
是"走一下、站一下"。现在多了一层**不问她**的东西：

- **11 个动作**：`eat drink sit nap window deskwork shelf door stretch wander greet`，
  每个是一串步骤（走到哪 → 站稳 0.7 s → `motion` 剪辑 → 用掉/恢复生理量 → 回来）。
  全部只用现有指令（`goto` / `motion` / `eat` / `drink` / `sleep` / `hold` / `free`），
  没有新增任何运动能力。
- **驱力**：`kcal / water / sleep / fat` 直接变成"饿/渴/困/累"，到阈值就去做。
- **钟点**：23–7 该睡、早上一遍伸懒腰、上午桌边、中午窗边、下午书架、晚上窗边 ——

### 五、转身：为什么以前"脚动人不动"（已修，2026-11-14 凌晨）

`web/vrm.js` 每根骨写的是**世界朝向**（`rest 世界四元数 → 当前方向`）。
这个乘法会把父骨的旋转全部抵掉，包括 `app.js` 给 `root.rotation.y = her.yaw - π/2` 的那一转 ——
所以模型永远保持绑定姿态的朝向，只有四肢跟着节点转。竖直骨（骨盆/胸/颈/头）更彻底：
rest 方向和当前方向都是"正上方"，`setFromUnitVectors` 给的是最小旋转，绕身体轴那一转压根没被约束。

**修法**：不猜角度和符号，直接拿髋线这个 3D 向量对齐 ——
加载时记 `restHip = normalize(leftUpperLegWorld − rightUpperLegWorld)`，
每帧 `nowHip = normalize(nodes[10] − nodes[14])`，`qBody.setFromUnitVectors(restHip, nowHip)`，
竖直骨在 `qDelta` 上左乘 `qBody`。两个水平向量的最短旋转就是绕竖轴那一转，方向由几何自己定。
（用"第一帧当零点 + `R_y(±θ)`"试过两次，都猜反了：绑定姿态 ≠ 第一帧姿态。）

**同一批补的骨**（原来"全身只有三块大区域能控制"就是这么来的）：
`spine`、`leftShoulder`/`rightShoulder`（这个模型没有 `upperChest`，日志里 `骨骼挂上 21/18 根`），
手指给一个静态轻握拳（必须写 normalized，每帧 `humanoid.update()` 会覆盖 raw），
hand 若落进躯干轴线 0.19 m 内沿径向推出来。

**CDP 量出来的**（无头 chromium + `Runtime.evaluate`，容器里 WebGL 起不来但数学照跑）：

| 量 | 修前 | 修后 |
|---|---|---|
| 她转身 33° 时胸的朝向 | 不动（≈2°） | 跟着转 32.6° |
| 髋线角 / 胸口朝向 | 无关联 | 逐帧一致（Δ −33.4° vs +32.6°） |
| 骨 vs 节点的方向误差 | — | 手臂 0.9~1.5°、手 4.3°、胸 2.3°、腿 2.2~2.5° |

### 四·五、转身的 180°：为什么"脚手身子"会对不上（2026-11-14 07:00）

髋线能定"生死线"，定不出"正反"：模型左右手系和 SOMA 节点左右手系只要差一个符号，
`qBody` 就整整差半圈 —— 身子朝前、脚朝后（或反过来），**看的人只会说"她倒着走/脚是反的"**。
试过的三条路：

1. `R_y(-θ)`、`R_y(+θ)` 配"第一帧当零点" —— 都猜反了，而且零点取自第一帧而不是绑定姿态；
2. 手动给 `restHip` 取反 —— 只是把 180° 挪到另一头，**整体转半圈，脚和身子的关系没变**；
3. **正解：拿脚当参照自校准。** 脚是**逐骨**对齐节点的（不经过 `qBody`），所以可信：
   把 rest 的"正面"（肩线 × 上）用 `qBody` 转过去，若和双脚平均朝向（踝→趾）点积为负，
   就给 `qBody` 左乘 `R_y(π)`。

CDP 实测：`eyeDir`（头→双眼）与双脚朝向夹角 **−1.9°**（散布 10°），双眼与肩线夹角 −91.9° ——
脸、脚、肩三者自洽，且这个判断每帧都做，不依赖型号约定。

## 身体朝向与声带（2026-11-14 凌晨第二次修）

### 1. "脚动人不动"：竖直的骨头算不出 yaw
`web/vrm.js` 的骨骼对齐是**逐骨绝对世界朝向**：`qDelta = setFromUnitVectors(rest.dir, 当前 dir)`。
这对腿/臂没问题（它们的 rest 方向是斜的，含 yaw 信息），但对**竖直骨**
（hips / chest / neck / head，rest 方向就是正上方）是退化的：`setFromUnitVectors`
只给"最小旋转"，绕自身轴的转角完全没被约束 → 脊柱永远保持绑定姿态的朝向，
只有四肢跟着节点转。视觉上就是**脚在走，人不动**。

修法：身体 yaw 从**髋骨连线**里取（`nodes[10]` 左髋 − `nodes[14]` 右髋，这根线是水平的，
绕 y 的角度就是她身子朝哪），相对第一次见到的姿态取 delta，再作为绕世界 y 的旋转
**左乘**到竖直骨的 `qDelta` 上。取负号的原因写在注释里：`R_y(θ)` 把 +z 送到 +x，
髋骨连线的角度是减的，直接用 delta 会朝反方向拧（走左边、身子往右转）。

离线验过（`/tmp/yawtest2.mjs`，用同一份 `vendor/three.module.js`）：
她转 0/30/90/180/−45/−120° → 身体朝向 0/−… 全部一一对上。

### 2. 声带：让用户自己接 TTS
原来只有 `voice.js` 里源-滤波器手搭的共振峰，机器味重。现在设置里多一组「声带」：

- 四格：**地址**（填到 `/audio/speech` 那一层）、**密钥**、**模型**、**音色** —— 存 `localStorage['soma.tts']`；
- 走 OpenAI 那套：`POST {url}`，`Authorization: Bearer {key}`，body `{input, response_format:'mp3', model?, voice?}`；
- 回来的音频直接用 `<audio>` 播（不占本地合成器）；`application/json` 也能吃（`audio` / `data` / `audio_content` 里的 base64）；
- **没填 → 还是本地合成；填了但请求失败 → 退回本地合成**（不会哑）；
- 面板状态行会显示"已接：模型/音色"，三个按钮：保存 / 试一句 / 清空。

**手是"反着长"的**：手骨没有子节点，只对齐方向时"绕骨轴转多少"是任意的
（`setFromUnitVectors` 给的是最小旋转），结果掌心朝外、手背贴身体 —— 看起来就是两只手反了。
修法不是猜一个 π：把掌心法线也钉住，用「骨轴 + 掌向」造完整正交基。

```js
/* vrm.js：手的两根骨给自己一个后向方向（前臂→手），并指定掌向 */
{ n: 6, bone: 'leftHand',  child: -1, from: 5, palm:  1 },
{ n: 9, bone: 'rightHand', child: -1, from: 8, palm: -1 },
```
```js
tmpPalm.set(latNow.x * def2.palm, 0, latNow.z * def2.palm);  /* latNow = 当前身体左侧 */
basisQuat(dirT, tmpPalm, qNewB);                             /* y=骨轴, z=掌向 */
qDelta.copy(qNewB).multiply(qRestB.invert());                /* rest 基 → 新基 */
```
两个坑：`nowHip` 在后面算 180° 消歧时会被**脚线**覆盖（变成 0.1 米量级的小向量），
拿它当掌向会退化成"朝前"——所以另存一个 `latNow`；`palm` 的正负只看一行实测
（`zDotLat` 左 −0.88 / 右 +0.88 = 双掌朝身体中线，正确）。

**站着转圈**：`vYawWant` 是"谁写谁负责"，没人写就沿用上一帧。走路时被限角压到 0.45 之后
站住，再没人清 —— 于是 0.45 rad/s 永久自转。修法：每帧开头 `W.vYawWant = 0.0f;`，
只有这一帧真有人要她转才写。加了 `vy src=N` 打点才看清是 `src=6`（限角那行）留的尾巴。

**画质**：MToon 描边（`outlineWidthMode='screenCoordinates'`、`outlineWidth=0.0022`、
雾墨色 0x2a2b30）、`envMapIntensity=0.55`、IBL 贴图 64→128。

#### 站立转圈：一共三个源头，逐个掐（2026-11-14）

1. **指令残留**：`vYawWant` 谁写谁负责，限角写进去的 0.45 在速度掉到 0 之后没人清 → 永久 0.45 rad/s。
   每帧开头清零，只有这一帧真有人要她转才写。
2. **绕障自激**：贴着家具站着时每帧都算接触 → 武装绕障 0.9 s → 0.85 rad/s 让她更贴家具 → 再武装。
   现在只看"想不想走"（`vDesWant > 0.15`），不看当前速度（原地转身时骨盆速度有 0.1~0.2 m/s，会骗人）。
3. **边界来回翻**：老代码用对称的 `|z| > 9.30`，可屋子是 `z ∈ [-3.25, 9.60]` —— 南墙根本没被拦，
   她走到 z=-2.9 贴墙，侧向捕获点 capL 到 -0.69，判摔（1 分钟摔 9 次）。
   改成 `LIM_X = 3.55 / LIM_ZMIN = -2.78 / LIM_ZMAX = 9.25`，并加 0.08/0.30 m 的滞回。

最后加了一道阀（不解释原因，只保证现象不出现）：位移判"站着"——一秒挪不到 6 cm 且
`|vYawWant| > 0.10` 连续 2.2 s，就掐掉转向 0.8 s。

实测（60 s 采样）：站立帧 2077 里"还在转"的 212 帧、最长连续 1.6 s（就是 goto 的转身），
摔 1 次/分钟（原 9 次）。

#### 绕障的另一半：不是"遇到就转"，是"撞上才绕"（同日下午）

`vYawWant` 被限角压到 0.45 / `impact≈0` 的贴蹭也会武装绕障 / 绕障时仍以 0.9 m/s 前进 ——
这三条叠起来就是"她以 0.9 m/s 边走边被转 0.45 rad/s"，轨迹打成螺旋、侧向捕获点 capL 冲到 0.97 判摔，
实测同一角落一分钟摔 8~11 次。现在：只有 `impact > 0.10`（真撞上）才武装、绕障只给 0.55 rad/s、
同时把速度压到 0.38、武器时长 0.6 s。

另外两处：
- 碰撞推出去一帧最多 5 cm（原来可能一帧推几十厘米，骨盆速度瞬间 1.2 m/s → 判摔）；
- "想走却挪不动"（一秒 <6 cm）到 2 s 就缓收速度（×0.45）并换闲逛相位，不一刀切 0（切 0 会冻住落脚点，反而摔）。

45 s 采样（SOMA_HABIT_OFF=1，站着不动的时间占多数）：摔 1 次，站立期间累计转角 2.8 rad（≈0.06 rad/s 的慢摆，不是自转）。

### 四·十五　"她为什么一直在生气"：疼不是状态，是事件（2026-11-14）

表情上线后第一版读数是 `cort 0.94 / pain 0.86 / adr 0.79`，她走路、坐着、发呆都挂着怒色。查下来不是表情公式的问题：

- 手/肩贴着墙走、身体蹭着家具时，**每一帧**都在算"接触"，
  `spikePain(min(0.22, 0.02*force*sens))` 一帧一次 → 不到半秒顶到 1.0，再也落不下来。
- 撞家具那条同理（`impact > 0.12` 每帧都成立），把皮质醇和肾上腺素一起喂满。
- 连带把 `stuck` 判据也调了：原来 `vDes > 0.05` 就算"想走"，收尾减速时被误判成"卡住"，stress 顶到 1。

改法（三条，全是"事件化"）：

| 项 | 原来 | 现在 |
|---|---|---|
| 末端接触疼 | 每帧、单次最多 0.22 | 同一部位 1.2 s 一次，单次 ≤0.05，力的门槛 1.2→2.2 |
| 撞家具疼 | 每帧、单次 0.30 | 全局 2.5 s 冷却，单次 ≤0.22，门槛 0.12→0.30 |
| 卡住→皮质醇 | `vDes > 0.05` | `vDes > 0.18`，且 `cBase` 里 stress 权重 0.35→0.28 |

改完（同一个人、同一条路走 40 s）：`cort 0.94 → 0.19`、`pain 0.86 → 0.00`、`adr 0.79 → 0.11`。
表情这时才是"跟着心情走"，而不是"跟着碰撞计数走"。
